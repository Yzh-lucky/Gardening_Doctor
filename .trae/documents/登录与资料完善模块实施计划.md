### 2.2 关键事实（决定了方案形状）

1. `wx.getUserProfile` 自 2022-10-25 起废弃，返回灰色默认头像 + “微信用户”。因此头像昵称**只能**用微信「头像昵称填写能力」：`<button open-type="chooseAvatar">` + `<input type="nickname">`。
2. `chooseAvatar` 回调拿到的 `e.detail.avatarUrl` 是**本地临时路径**，无法直接作为 `avatar_url` 持久化 → 必须有服务端上传。这正是本轮新增 `POST /user/avatar` 的唯一原因。
3. `PUT /user/profile` 对 `nickname` / `avatar_url` 都是「非空才更新」，所以**不要传空字符串**，否则语义被误用。
4. `app.json` 当前 7 个页面、**无 tabBar**（[app.json](file:///d:/Programs/AI-Gardening-doctor/miniprogram/app.json)），`wx.redirectTo` 可指向任意页面，不受 tabBar 限制。
5. 项目里**没有** `wx.uploadFile` 的封装，也没有任何 `chooseAvatar` / `type="nickname"` 用法（已全项目 grep 确认），因此本轮不修改任何已有上传代码。
6. **「保持静默登录」的副作用**：不清除登录态拦截的前提下，退出登录只能是「软退出」——清掉本地 token 并跳到登录页，但若用户回退到其它页面，`ensureLogin()` 会再次静默登录。这是所选方案固有限制，不在本轮解决（要硬退出必须改 `utils/auth.js::ensureLogin`，违反「不改动已实现模块」约束）。

```python
"""头像上传接口（新增模块，不修改任何已有接口）。

POST /user/avatar：登录用户上传单张头像，复用 services/storage 的魔数与大小校验、
sha256 去重落盘，返回可持久化的 avatar_url；再由已有的 PUT /user/profile 写入用户资料。
"""
from fastapi import APIRouter, File, UploadFile

from app.core.deps import CurrentUserId
from app.core.response import ApiResponse, ok
from app.schemas.avatar import AvatarOut
from app.services.storage import process_image

router = APIRouter(prefix="/user", tags=["user"])


@router.post("/avatar", response_model=ApiResponse[AvatarOut], summary="上传头像")
async def upload_avatar(
    user_id: CurrentUserId,
    file: UploadFile = File(..., description="头像图片，单张 ≤ 2MB，支持 jpg/jpeg/png/webp"),
) -> ApiResponse[AvatarOut]:
    # user_id 仅用于鉴权（未登录返回 1001/401），不写库，写库统一交给 PUT /user/profile
    content = await file.read()
    image = process_image(content, file.filename or "")
    return ok(AvatarOut(avatar_url=image.url))
```

**为什么独立文件而不是加进 `routers/user.py`**：项目/用户硬约束是「新增模块不得改动原有已实现的功能模块代码」。
独立文件可以做到对已有后端代码**零逻辑改动**，代价只是 `main.py` 多两行注册。

**为什么不用 `UploadFile` 之外的多格式兼容**：头像只有单文件一个场景，沿用标准 multipart 即可；
`process_image` 已按魔数校验，非法格式抛 `2002`、超 2MB 抛 `2003`（HTTP 413），错误语义与识别链路完全一致。

#### 新建 `backend/tests/test_user_avatar.py`

沿用 [conftest.py](file:///d:/Programs/AI-Gardening-doctor/backend/tests/conftest.py) 的 `client` + `auth` 夹具（`auth` 用 `mock_` 前缀 code 登录取 token，用后自动清理用户数据），覆盖 4 条：

### 3.2 前端：新增 `utils/upload.js`

```javascript
// 头像上传：wx.uploadFile 单文件 → POST /user/avatar；token 失效时静默重登并只重发一次
const { baseUrl, debug } = require('../config');
const { getToken, login } = require('./auth');

function doUpload(filePath, retried) {
  return new Promise((resolve, reject) => {
    wx.uploadFile({
      url: baseUrl + '/user/avatar',
      filePath,
      name: 'file',
      header: { Authorization: 'Bearer ' + getToken() },
      timeout: 20000,
      success(res) {
        // 小程序上传接口返回的是字符串，必须手动 JSON.parse
        let body = {};
        try {
          body = JSON.parse(res.data || '{}');
        } catch (e) {
          body = {};
        }
        if (body.code === 0 && body.data) {
          return resolve(body.data.avatar_url);
        }
        if ((body.code === 1001 || body.code === 1002 || res.statusCode === 401) && !retried) {
          return login({ silent: true })
            .then(() => doUpload(filePath, true))
            .then(resolve)
            .catch(reject);
        }
        if (debug) {
          console.warn('[upload] 头像上传失败', body.code, body.message, body.trace_id);
        }
        reject(body);
      },
      fail(err) {
        if (debug) {
          console.warn('[upload] 网络异常', err);
        }
        reject({ code: -1, message: '网络异常，请重试' });
      },
    });
  });
}

/** 上传本地头像文件，resolve 服务端可持久化的 avatar_url */
function uploadAvatar(filePath) {
  return doUpload(filePath, false);
}

module.exports = { uploadAvatar };
```

> 注意点：`wx.uploadFile` 只支持单文件（项目已知约定），响应体是字符串（项目已有 lessons learned），
> `Authorization` 需手写 header（`request.js` 的 header 逻辑不适用于 uploadFile）。

#### `pages/login/login.js`（只做视图与登录编排，不改任何已有 util 行为）

```javascript
const { login } = require('../../utils/auth');
const { uploadAvatar } = require('../../utils/upload');
const { compressImage } = require('../../utils/image');

Page({
  data: { agreed: false, nickname: '', avatarTempPath: '', loading: false },

  onChooseAvatar(e) {
    this.setData({ avatarTempPath: e.detail.avatarUrl || '' });
  },

  onNicknameInput(e) {
    this.setData({ nickname: (e.detail.value || '').trim() });
  },

  toggleAgree() {
    this.setData({ agreed: !this.data.agreed });
  },

  goPrivacy() {
    wx.navigateTo({ url: '/pages/privacy/privacy' });
  },

  async onLogin() {
    if (!this.data.agreed) {
      wx.showToast({ title: '请先阅读并同意隐私政策', icon: 'none' });
      return;
    }
    if (this.data.loading) return;
    this.setData({ loading: true });
    try {
      const profile = {};
      if (this.data.nickname) profile.nickname = this.data.nickname;
      if (this.data.avatarTempPath) {
        // 先压缩（≤2MB），再上传拿到可持久化的 avatar_url
        const small = await compressImage(this.data.avatarTempPath, 70);
        profile.avatar_url = await uploadAvatar(small);
      }
      await login({ silent: false, profile });
      wx.showToast({ title: '登录成功', icon: 'success' });
      setTimeout(() => wx.navigateBack({ delta: 1 }), 600);
    } catch (err) {
      // request/upload 内部已 toast，这里只兜底（用户取消选择头像等）
    } finally {
      this.setData({ loading: false });
    }
  },
});
```

**边界处理**：
- `profile` 里**只放非空字段**——后端 `PUT`/`login` 都是「非空才写」，传空串会误用语义。
- `avatarTempPath` 为空时不传 `avatar_url`，用户资料里原头像保持不变。
- 登录成功用 `wx.navigateBack()` 回到个人中心，其 `onShow → loadProfile()` 会自动刷新出新昵称/头像，无需额外跳转逻辑。
- 用户在选择头像后中途取消 / 上传失败：`catch` 静默返回（`request`/`upload` 层已弹 toast），`loading` 复位。

```javascript
const { ensureLogin, fetchProfile, updateProfile } = require('../../utils/auth');
const { uploadAvatar } = require('../../utils/upload');
const { compressImage } = require('../../utils/image');

Page({
  data: { nickname: '', avatarUrl: '', avatarTempPath: '', loading: true, saving: false },

  onLoad() {
    ensureLogin()
      .then(() => fetchProfile())
      .then((profile) => {
        this.setData({
          nickname: profile.nickname || '',
          avatarUrl: profile.avatar_url || '',
          loading: false,
        });
      })
      .catch(() => this.setData({ loading: false }));
  },

  onChooseAvatar(e) {
    this.setData({ avatarTempPath: e.detail.avatarUrl || '' });
  },

  onNicknameInput(e) {
    this.setData({ nickname: (e.detail.value || '').trim() });
  },

  async onSave() {
    const nickname = this.data.nickname;
    if (!nickname) {
      wx.showToast({ title: '请填写昵称', icon: 'none' });
      return;
    }
    if (this.data.saving) return;
    this.setData({ saving: true });
    try {
      const payload = { nickname };
      // 只有用户重新选了头像才上传，避免每次都写一份文件
      if (this.data.avatarTempPath) {
        const small = await compressImage(this.data.avatarTempPath, 70);
        payload.avatar_url = await uploadAvatar(small);
      }
      await updateProfile(payload);
      const app = getApp();
      if (app && app.globalData) app.globalData.userInfo = null; // 让下次进个人中心重新拉取
      wx.showToast({ title: '已保存', icon: 'success' });
      setTimeout(() => wx.navigateBack({ delta: 1 }), 600);
    } catch (err) {
      // toast 已由 request/upload 层处理
    } finally {
      this.setData({ saving: false });
    }
  },
});
```

`pages/profile/profile.wxss`：只写 `.avatar-picker` / `.avatar-lg`（与登录页同款，各页独立定义，不污染 app.wxss）、`.nickname-input`、`.input-ph`、`.counter` 等私有类。

## 4. Assumptions & Decisions

| # | 决策 | 依据 / 影响 |
| --- | --- | --- |
| A1 | `POST /user/avatar` 放在**新文件** `routers/avatar.py`，不写进 `routers/user.py` | 满足「新增模块不得改动原有已实现的功能模块代码」，后端已有业务代码零逻辑改动 |
| A2 | 上传接口**只落盘不写库**，写库仍走已有的 `PUT /user/profile` | 让「上传」与「资料写入」职责单一；已有接口语义不被改变 |
| A3 | 「退出登录」采用 `clearToken` + `wx.redirectTo` 登录页，**不新增全局登录拦截** | 落实「保持静默登录」；`redirectTo` 用于把会自动重登的「我的」页移出栈 |
| A4 | 保留现有「重新登录」行不动，另外追加「退出登录」 | 纯追加 = 零风险；两者语义确有差异（原地重登 vs 跳登录页）。若后续觉得并列冗余，可单独提出再合并 |
| A5 | 不做账号注销、手机号绑定 | 用户在模块边界选择中明确未选 |
| A6 | 不启用 `app.json` 的 `__usePrivacyCheck__` / `wx.requirePrivacyAuthorize` | 属 T3.8 隐私接入范畴，开启会改变全局页面行为；本轮只用页内勾选做软门槛 |
| A7 | 头像上传前统一 `compressImage(..., 70)` | 复用 `utils/image.js` 已导出能力，规避 `2003` 图片过大 |
| A8 | 昵称输入上限 24 字（后端硬上限 64） | 纯 UI 约束，后端 `max_length=64` 不变 |

### 需要向用户明确告知的两点风险

1. **「退出登录」是软退出**：因为保持静默登录且不修改 `utils/auth.js`，用户回退到首页/结果页等页面时仍会被 `ensureLogin()` 静默重新登录。这是所选方案的固有限制；若要硬退出，必须改 `utils/auth.js::ensureLogin`（违反当前约束，需另行确认）。
2. **微信审核合规**：微信要求提供注册/登录的小程序必须有**账号注销**入口。本模块不含注销，可能影响 [任务清单.md](file:///d:/Programs/AI-Gardening-doctor/任务清单.md) 中 T4.6 提审。本轮不擅自实施，作为风险提示。
3. 微信「头像昵称填写能力」需**基础库 ≥ 2.21.2**，真机验证时请注意。
